# Camera Attendance AI

**Автоматическая посещаемость школ по обычным IP-камерам в классах.** AI сам узнаёт детей на уроке, сверяет с расписанием и ставит «присутствует / опоздал / отсутствует». Учителю ничего отмечать не нужно; вмешиваться он может, но не обязан.

- **Сервер платформы**: только стандартная библиотека Python 3.10+ (без внешних зависимостей), SQLite.
- **AI-воркер**: OpenCV YuNet (детектор) + SFace (распознавание), ~40 МБ моделей, работает на CPU. Один процесс обслуживает все камеры школы.
- Роли: **супер-админ** (все школы) → **админ школы** → **учитель**.

## Как это работает

```
IP-камеры в классах ──RTSP──► face_worker.py (одна служба на школу) ──токен школы──► app.py (платформа)
                               │ включает камеру только на время её уроков            │ расписание уроков
                               │ находит лица, проверяет размер и резкость            │ авто-журнал по урокам
                               │ сравнивает с фото учеников, подтверждает в 3+ кадрах │ опоздания и отсутствие
                               └ сигнал «камера работает» раз в минуту                └ роли, аудит
```

### Автоматические решения по каждому уроку

| Что увидела система | Отметка (без участия человека) |
|---|---|
| Ребёнок узнан уверенно (≥ 0.45) в нескольких кадрах | **Присутствует**, а если пришёл позже порога, **Опоздал** |
| Ребёнок 2+ раза узнан со средней уверенностью (0.363–0.45) | **Присутствует / Опоздал**: повторное совпадение считается подтверждением |
| Камера исправно работала весь урок, а ребёнка в кадре не было | **Отсутствует** (настройка школы, по умолчанию включена) |
| Урок без камеры, турникет работал, а ребёнок через него не проходил | **Отсутствует** |
| Одно слабое совпадение за весь урок | **Проверить**: единственный случай, когда нужен человек |
| Камера была офлайн или лица слишком мелкие | **Нет данных**: система не гадает, чтобы поломка не сделала «отсутствующим» весь класс |
| Похожие дети (близнецы) | Если разница между кандидатами < 0.04, событие не засчитывается |
| Вторая модель (ArcFace) подтвердила совпадение (≥ 0.40) | **Присутствует / Опоздал**, даже если основная модель не уверена |
| Вторая модель возразила (< 0.20) | Совпадение отбрасывается как «чужой ребёнок» |

### Вторая модель: «AI-проверка»

Когда основная модель (SFace) находит похожего ребёнка, лицо дополнительно проверяет более сильная модель ArcFace R50. Она работает локально, без отправки фото в интернет, и запускается только на уже найденных совпадениях, поэтому нагрузку почти не добавляет. На реальной камере она подняла оценку «своих» пар с 0.38 до 0.51 и опустила «чужих» с 0.21 до 0.06.

```powershell
.venv\Scripts\python face_worker.py --download-verifier   # ~290 МБ, проверка SHA-256
```

Воркер подхватывает модель автоматически; без неё работает как раньше (`--no-verifier` отключает). **Лицензия:** готовые модели InsightFace разрешены только для **некоммерческого** использования. Для коммерческого продукта купите лицензию InsightFace или подставьте свою 512-мерную ONNX-модель через `--verifier путь.onnx` (вход: выровненное лицо 112×112).

Любую отметку можно исправить кликом в журнале, и ручная отметка всегда главнее автоматической. Авто-отсутствие отключается в «Камеры и AI → Параметры».

Замеры на тестовых изображениях: лицо 120 px даёт схожесть 0.95, 80 px — 0.82, 60 px при сильном сжатии — 0.55, 45 px — 0.40. Лицо меньше ~35 px не детектируется. У чужих лиц схожесть 0.10–0.24.

## Быстрый старт (Windows PowerShell)

```powershell
cd camera-attendance-ai-stage1
py -3 manage.py create-superadmin --username superadmin     # пароль сгенерируется и будет показан один раз
py -3 manage.py seed-demo                                   # необязательно: 3 тестовые школы с расписанием и событиями
py -3 app.py                                                # http://127.0.0.1:8080
```

Демо-школы получают в названии суффикс «(тест)». Фото в них — синтетические мультяшные аватары, а не реальные дети. Пересоздать демо-данные: `py -3 manage.py seed-demo --reset`.

## Подключение школы к автоматическому режиму

1. **Школы** (супер-админ): создать школу. **Пользователи**: администратор школы и учителя.
2. **Классы и ученики**: классы, ученики, 2–5 чётких фото лица на каждого, согласие родителей.
3. **Камеры и AI**: добавить камеры кабинетов (тип «Камера в классе»).
4. **Расписание**: уроки с привязкой к камере кабинета.
5. На компьютере в одной сети с камерами (один раз):

```powershell
py -3 -m venv .venv
.venv\Scripts\pip install -r requirements-ai.txt
.venv\Scripts\python face_worker.py --download-models          # модели + проверка SHA-256
py -3 manage.py worker-config --school-id 1                    # токен + data\cameras-school-1.json со всеми камерами школы
notepad data\cameras-school-1.json                             # вписать RTSP-адрес каждой камеры
powershell -ExecutionPolicy Bypass -File scripts\install_autostart.ps1
```

После этого платформа и AI сами запускаются при входе в Windows и перезапускаются при сбое. AI каждые 2 минуты берёт расписание с платформы и включает камеру за 10 минут до её урока, а после урока отключает. Камеры входа работают с 1,5 ч до первого урока до 30 мин после последнего. Логи пишутся в `data\logs\`. Удалить автозапуск: `install_autostart.ps1 -Uninstall`.

Формат `cameras-school-N.json` (файл лежит в `data/`, в git не попадает):

```json
{
  "api": "http://127.0.0.1:8080",
  "token": "cat_...",
  "cameras": {
    "room201": "rtsp://USER:PASSWORD@192.168.1.21:554/Streaming/Channels/101",
    "gate": "rtsp://USER:PASSWORD@192.168.1.10:554/Streaming/Channels/101"
  }
}
```

Проверить распознавание без камер: добавьте себя учеником, загрузите 2–3 своих фото и запустите
`.venv\Scripts\python face_worker.py --camera-key <камера> --source 0 --show --always-on` (веб-камера ноутбука).

Другие ключи воркера: `--check-photos` проверяет загруженные фото (в панели появится «Лицо OK» или «Лицо не найдено»), `--always-on` включает камеры круглосуточно без учёта расписания, `--fps` задаёт число кадров в секунду на камеру (по умолчанию 2). Пароли из RTSP-адресов в логи не пишутся.

### Требования к камерам

- Используйте **основной поток** (1080p, у Hikvision это `/Streaming/Channels/101`), а не sub-stream 640×360.
- Лицо в кадре должно быть **от 40 px** в ширину, лучше 60+. Камера над доской, направлена на парты.
- Если в кадре мало света, включите на камере WDR/подсветку. Лица против окна распознаются хуже.
- Один современный CPU тянет 4–8 камер при 2 кадрах/с. Камеры без уроков процессор не нагружают.

## Безопасность и защита данных

- Пароли хешируются PBKDF2-SHA256 (600 000 итераций). Токены устройств и сессий хранятся только как SHA-256.
- Сессия в cookie `HttpOnly; SameSite=Strict` (+ `Secure` с флагом `--secure-cookies`), CSRF-токен на все изменения.
- Защита от перебора: блокировка учётной записи на 15 минут после 5 ошибок, лимит попыток с одного IP, единое сообщение об ошибке (по нему нельзя узнать, существует ли логин).
- Изоляция школ: каждый запрос проверяет `school_id`. Токен устройства даёт доступ только к своей школе.
- Фото выдаются только авторизованным пользователям своей школы, с заголовками `no-store` и `nosniff`. Загрузка принимает только JPEG/PNG до 3 МБ (проверка по сигнатуре файла).
- Строгий CSP без inline-скриптов, `X-Frame-Options: DENY`, интерфейс строится без `innerHTML`.
- На Windows порт открывается с `SO_EXCLUSIVEADDRUSE`, чтобы другой процесс не мог перехватить его.
- Кадры с камер и вырезанные лица **не сохраняются**. Шаблоны лиц существуют только в памяти воркера.
- Аудит: входы, неудачные попытки, все изменения данных.
- Удаление ученика удаляет его фото и события. Удаление школы удаляет все её данные.

**Для работы по сети** запускайте за HTTPS reverse proxy (nginx, Caddy): `py -3 app.py --host 0.0.0.0 --allow-remote --secure-cookies --trust-proxy`. Не выставляйте RTSP-камеры и порт платформы напрямую в интернет.

**Правовое.** Фото детей являются персональными данными несовершеннолетних. Перед реальным запуском нужно письменное согласие родителей, назначенный ответственный, политика хранения (`manage.py purge --days 365`) и, по возможности, проверка у юриста (в Узбекистане это закон «О персональных данных»).

## Интеграция СКУД / Hikvision ISAPI

Турникеты и терминалы тоже отмечают вход в школу (тип камеры «Вход»). Для уроков без камеры в кабинете присутствие считается по входу в школу.

```powershell
pip install -r requirements-bridge.txt
$env:HIK_PASSWORD = "DEVICE_PASSWORD"; $env:ATTENDANCE_INGEST_TOKEN = "cat_..."
py -3 isapi_bridge.py --host 192.168.1.30 --camera-key school_gate --api http://127.0.0.1:8080 --allowed-minor <код успешного прохода>
```

## API для устройств (заголовок `X-Ingest-Token`)

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/api/ingest` | событие: `face_match`, `access_granted`, `motion`, … |
| POST | `/api/worker/heartbeat` | `{"camera_key": "...", "ok": true, "idle": false}` раз в минуту |
| GET | `/api/worker/schedule` | окна работы каждой камеры на сегодня |
| GET | `/api/worker/roster` | ученики школы с фото (для воркера) |
| GET | `/api/worker/photos/<id>` | эталонное фото |
| POST | `/api/worker/photos/<id>/quality` | результат проверки фото |

## Состав

- `app.py` — HTTP API, сессии, роли, раздача панели.
- `core.py` — хранилище, движок автоматической посещаемости, изоляция школ, аудит.
- `manage.py` — CLI: супер-админ, пароли, конфиг воркера, демо-данные, очистка.
- `face_worker.py` — AI-распознавание для всех камер школы по расписанию.
- `scripts/install_autostart.ps1` — автозапуск платформы и AI в Windows.
- `isapi_bridge.py`, `rtsp_motion_bridge.py` — мосты Hikvision ISAPI и детектор движения.
- `web/` — панель (без внешних библиотек). `tests/` — автотесты.

## Известные ограничения

- Защиты от подмены лица фотографией (liveness) нет. Частично спасают требование нескольких кадров и камера под потолком.
- Точность зависит от камеры и света. Перед запуском проверьте на 1–2 классах и подберите пороги в «Камеры и AI → Параметры».
- SQLite рассчитан примерно на десятки школ. Для крупной сети нужен переход на PostgreSQL.
