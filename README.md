# Camera Attendance AI

Платформа учёта посещаемости школ по обычным IP-камерам в классах: распознавание лиц на AI-воркере, расписание уроков, журнал с ручной корректировкой, несколько школ на одной платформе.

- **Сервер платформы**: только стандартная библиотека Python 3.10+ (без внешних зависимостей), SQLite.
- **AI-воркер**: OpenCV YuNet (детектор) + SFace (распознавание), ~40 МБ моделей, работает на CPU.
- Роли: **супер-админ** (все школы) → **админ школы** → **учитель**.

## Как это работает

```
IP-камера в классе ──RTSP──► face_worker.py ──HTTPS + токен школы──► app.py (платформа)
                              │ детекция лица (YuNet)                  │ расписание уроков
                              │ проверка размера и резкости            │ журнал по урокам
                              │ сравнение с фото учеников (SFace)      │ очередь проверки
                              │ подтверждение в 3+ кадрах              │ ручные отметки
                              └ heartbeat «камера работает» раз в мин  └ роли и аудит
```

### Почему отметкам можно доверять, даже если камера старая

| Ситуация | Что делает система |
|---|---|
| Ребёнок узнан уверенно (≥ 0.45) в нескольких кадрах | **Присутствует** / **Опоздал** (по времени и расписанию) |
| Узнан неуверенно (0.363–0.45): далеко, темно, поворот головы | **Проверить**: попадает в очередь учителю, а не в журнал |
| Камера работала, но ребёнка не узнала | **Не замечен**: учитель подтверждает отсутствие одним кликом |
| Камера была офлайн или лица слишком мелкие | **Нет данных**: система **никогда** не ставит «отсутствует» сама |
| Похожие дети (близнецы) | Если разница между двумя кандидатами < 0.04, событие не отправляется |
| Учитель отметил вручную | Ручная отметка всегда важнее автоматической |

Замеры на тестовых изображениях: лицо 120 px даёт схожесть 0.95, 80 px — 0.82, 60 px при сильном сжатии — 0.55, 45 px — 0.40 (уходит на проверку). Лицо меньше ~35 px не детектируется. У чужих лиц схожесть 0.10–0.24.

## Быстрый старт (Windows PowerShell)

```powershell
cd camera-attendance-ai-stage1
py -3 manage.py create-superadmin --username superadmin     # пароль сгенерируется и будет показан один раз
py -3 manage.py seed-demo                                   # необязательно: 3 тестовые школы с расписанием и событиями
py -3 app.py                                                # http://127.0.0.1:8000
```

Демо-школы получают в названии суффикс «(тест)». Фото в них — синтетические мультяшные аватары, а не реальные дети. Пересоздать демо-данные: `py -3 manage.py seed-demo --reset`.

Другие команды:

```powershell
py -3 manage.py set-password --username superadmin          # сброс пароля (новый будет сгенерирован)
py -3 manage.py set-password --username superadmin --prompt # ввести пароль вручную
py -3 manage.py purge --days 365                            # удалить события старше года
py -3 app.py --port 8080                                    # другой порт
```

## Порядок настройки школы

1. **Школы** (супер-админ): создать школу.
2. **Пользователи**: создать администратора школы и учителей (пароль генерируется и показывается один раз).
3. **Классы и ученики**: классы, ученики, 2–5 чётких фото лица на каждого. Обязательна отметка о согласии родителей.
4. **Камеры и AI**: добавить камеры кабинетов (тип «Камера в классе»).
5. **Расписание**: уроки с привязкой к камере кабинета.
6. **Токены устройств**: создать токен для AI-воркера.
7. Запустить воркер на компьютере в сети камер (см. ниже).

## AI-воркер для камер (один процесс на камеру)

```powershell
py -3 -m venv .venv
.venv\Scripts\pip install -r requirements-ai.txt
.venv\Scripts\python face_worker.py --download-models        # скачивает модели и сверяет SHA-256

$env:ATTENDANCE_INGEST_TOKEN = "cat_..."                       # токен из раздела «Токены устройств»
$env:ATTENDANCE_RTSP_URL = "rtsp://USER:PASS@192.168.1.20:554/Streaming/Channels/101"
.venv\Scripts\python face_worker.py --camera-key room201 --api http://127.0.0.1:8000
```

- `--source 0` — веб-камера ноутбука, `--source video.mp4` — видеофайл (удобно для тестов).
- `--check-photos` — только проверить загруженные фото (статусы «Лицо OK» / «Лицо не найдено» появятся в панели).
- `--show` — окно отладки с рамками лиц (зелёная: лицо достаточно крупное, красная: слишком мелкое).
- Логин и пароль камеры из RTSP-адреса никогда не попадают в логи.

Самый простой способ проверить распознавание без камер: создайте себя учеником, загрузите 2–3 своих фото и запустите воркер с `--source 0 --show`.

### Требования к камерам

- Используйте **основной поток** (1080p, у Hikvision это `/Streaming/Channels/101`), а не sub-stream 640×360.
- Лицо в кадре должно быть **от 40 px** в ширину, лучше 60+. Камера над доской, направлена на парты.
- Если в кадре мало света, включите на камере WDR/подсветку. Лица против окна распознаются хуже.
- 2 кадра/с (`--fps 2`) на камеру достаточно; один современный CPU тянет 4–8 камер.

## Безопасность и защита данных

- Пароли хешируются PBKDF2-SHA256 (600 000 итераций). Токены устройств и сессий хранятся только как SHA-256.
- Сессия в cookie `HttpOnly; SameSite=Strict` (+ `Secure` с флагом `--secure-cookies`), CSRF-токен на все изменения.
- Защита от перебора: блокировка учётной записи на 15 минут после 5 ошибок, лимит попыток с одного IP.
- Изоляция школ: каждый запрос проверяет `school_id`. Токен устройства даёт доступ только к своей школе.
- Фото выдаются только авторизованным пользователям своей школы, с заголовками `no-store` и `nosniff`. Загрузка принимает только JPEG/PNG до 3 МБ (проверка по сигнатуре файла).
- Строгий CSP без inline-скриптов, `X-Frame-Options: DENY`, интерфейс строится без `innerHTML`.
- На Windows порт открывается с `SO_EXCLUSIVEADDRUSE`, чтобы другой процесс не мог перехватить его.
- Кадры с камер и вырезанные лица **не сохраняются**. Шаблоны лиц существуют только в памяти воркера.
- Аудит: входы, неудачные попытки, все изменения данных.
- Удаление ученика удаляет его фото и события. Удаление школы удаляет все её данные.

**Для работы по сети** запускайте за HTTPS reverse proxy (nginx, Caddy):

```powershell
py -3 app.py --host 0.0.0.0 --allow-remote --secure-cookies --trust-proxy
```

Не выставляйте RTSP-камеры и порт 8000 напрямую в интернет.

**Правовое.** Фото детей являются персональными данными несовершеннолетних. Перед реальным запуском нужно письменное согласие родителей, назначенный ответственный, политика хранения (`manage.py purge`) и, по возможности, проверка у юриста (в Узбекистане это закон «О персональных данных»).

## Интеграция СКУД / Hikvision ISAPI

Турникеты и терминалы тоже могут отмечать вход в школу (тип камеры «Вход»). Для уроков без камеры в кабинете присутствие считается по входу в школу.

```powershell
pip install -r requirements-bridge.txt
$env:HIK_PASSWORD = "DEVICE_PASSWORD"; $env:ATTENDANCE_INGEST_TOKEN = "cat_..."
py -3 isapi_bridge.py --host 192.168.1.30 --camera-key school_gate --allowed-minor <код успешного прохода из документации>
```

`employeeNoString` на терминале должен совпадать с кодом ученика. Подробности и ограничения описаны в комментариях в `isapi_bridge.py`.

## API для устройств (заголовок `X-Ingest-Token`)

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/api/ingest` | событие: `face_match`, `access_granted`, `motion`, … |
| POST | `/api/worker/heartbeat` | `{"camera_key": "...", "ok": true}` раз в минуту |
| GET | `/api/worker/roster` | ученики школы с фото (для воркера) |
| GET | `/api/worker/photos/<id>` | эталонное фото |
| POST | `/api/worker/photos/<id>/quality` | результат проверки фото |

## Состав

- `app.py` — HTTP API, сессии, роли, раздача панели.
- `core.py` — хранилище, правила посещаемости, изоляция школ, аудит.
- `manage.py` — CLI: супер-админ, пароли, демо-данные, очистка.
- `face_worker.py` — AI-распознавание для RTSP-камер.
- `isapi_bridge.py`, `rtsp_motion_bridge.py` — мосты Hikvision ISAPI и детектор движения.
- `web/` — панель администратора (без внешних библиотек).
- `tests/` — автотесты.

## Известные ограничения

- Защиты от подмены лица фотографией (liveness) нет. Частично спасают требование нескольких кадров, камера под потолком и проверка учителем.
- Точность зависит от камеры и света. Перед запуском проверьте на 1–2 классах и подберите пороги в «Камеры и AI → Параметры».
- SQLite рассчитан примерно на десятки школ. Для крупной сети нужен переход на PostgreSQL.
